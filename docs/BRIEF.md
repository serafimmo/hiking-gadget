### Требования, извлечённые из ТЗ (чек-лист)

- R1. Карусель из 5 экранов: Главный → Секундомер → Таймер → Компас → Настройки.
- R2. Две кнопки-«стрелочки» листают экраны, две другие выполняют действия текущего экрана.
- R3. Главный: время (изначально берётся с компьютера, пояс по умолчанию МСК, меняется в настройках), дата, температура, влажность, заряд аккумулятора (аккумулятора пока нет — заготовка на будущее).
- R4. Секундомер: одна кнопка старт/стоп, другая — круг (lap).
- R5. Таймер: пресеты 1/3/5/10/30/60 мин; одна кнопка выбирает, другая запускает/останавливает.
- R6. **При переключении экранов все значения сохраняются** (секундомер и таймер продолжают идти в фоне, ничего не сбрасывается).
- R7. Компас: красивый круг со сторонами света, стрелка обновляется динамически, плавно.
- R8. Настройки: часовой пояс (популярные), интервал подогрева датчика SHT45 (у SHT4x действительно есть встроенный нагреватель), плюс прочие полезные.
- R9. Гашение экрана для экономии батареи.
- R10. Красивый UI: «современный хай-тек минимализм», приятно глазу.
- R11. Arduino IDE.

## 2. Железо (факты)

| Узел | Подключение | Примечания |
|---|---|---|
| ESP32-S3 SuperMini | — | Нативный USB (GPIO19/20), отдельного USB-UART чипа нет. Обычно 4 МБ flash. Плата в IDE: «ESP32S3 Dev Module». |
| OLED 0.96" 128×64, белый, SSD1306, I2C 0x3C | SCL=11, SDA=10 (своя шина, Wire1) | Модуль со **встроенными 4 кнопками**. |
| Кнопки модуля OLED | K1=GPIO4, K2=GPIO5, K3=GPIO6, K4=GPIO1 | Кнопки стоят **вертикальной колонкой справа от экрана**, сверху вниз нарисованы символы **^ v # \***. На разъёме подписи `GND VCC SCL SDA K4 K3 K2 K1`. Наиболее вероятное соответствие: K1=^, K2=v, K3=#, K4=\*. Это **не проверено на железе**, поэтому маппинг задаётся в одном месте конфига. «Стрелочки» из ТЗ — это ^ и v. Есть ли на модуле внешние подтяжки, неизвестно → INPUT_PULLUP, активный уровень LOW. |
| SHT45 (temp/RH), I2C 0x44 | Wire: SDA=8, SCL=7 | В объявлении написано «GY-SHT31-D…», вариант «SHT45». Что пришёл именно SHT4x, **не подтверждено**. По адресу 0x44 может оказаться и SHT3x — у него другой набор команд. |
| GY-273 магнитометр | Та же шина Wire (SDA=8, SCL=7), DRDY=GPIO12 | В названии товара QMC5883L (0x0D), но **на шёлкографии платы написано HMC5883L**. Под маркой GY-273 продают QMC5883L (0x0D), QMC5883P (0x2C) и HMC5883L (0x1E). Нужно автоопределение. Ориентация осей зависит от того, как плата стоит в корпусе. |
| Аккумулятор | пока нет | Заготовка: модуль батареи с «нет данных». Если позже поставят делитель напряжения, должно хватить одной строки в конфиге. |
| Зуммер / вибро | нет | Сигнал таймера только визуальный. |

Свободные/запрещённые пины ESP32-S3: strapping-пины GPIO0, 3, 45, 46. USB — это GPIO19/20. GPIO1 — **обычный** пин (утверждение v1, что это USB D−, неверно).

## 3. Среда сборки (есть на этой машине)

- Тулчейн установлен на втором диске, **системный диск заполнен (3 ГБ свободно) — ничего крупного на `/` не писать**, сборку, кэш и временные файлы класть в `/mnt/wd/arduino-esp32/`.
- `downloads.arduino.cc` **заблокирован (403)**. Ядро ESP32 и библиотеки ставятся только с GitHub.
- Команда сборки (FQBN должен включать USB CDC). Ядро ESP32 **3.3.12**:
  ```
  export TMPDIR=/dev/shm/arduino-esp32/tmp
  A="/mnt/wd/arduino-esp32/bin/arduino-cli --config-file /mnt/wd/arduino-esp32/arduino-cli.yaml"
  $A compile --fqbn esp32:esp32:esp32s3:CDCOnBoot=cdc --build-path /dev/shm/arduino-esp32/build/<уникальное-имя> Hiking_Gadget
  ```
  Рабочая часть тулчейна лежит в RAM-диске `/dev/shm/arduino-esp32` (NTFS через FUSE однопоточный и в 6+ раз медленнее). Полная сборка с нуля занимает ~45 с. Если `/dev/shm/arduino-esp32` пропал (перезагрузка), запустить `/mnt/wd/arduino-esp32/ramcache.sh`. Каждому параллельному сборщику нужен свой `--build-path`. Строки `Error initializing instance ... 403` — шум от заблокированного индекса, на сборку не влияют.
  - `ctags` подменён заглушкой (настоящий качается с заблокированного сервера), поэтому автопрототипы в `.ino` не генерируются. `.ino` должен содержать только `setup()`/`loop()` и вызовы в модули; весь код — в `src/`.
- Внешние библиотеки: только то, что можно поставить с GitHub. Сейчас установлен **U8g2** (olikraus/U8g2_Arduino). Датчики лучше писать на «сыром» I2C без библиотек.
- На хосте есть g++ 13, make, cmake, Python 3 с PIL. С их помощью можно собирать UI-код и логику на хосте: рендер экранов в PNG **из настоящего кода прошивки**, unit-тесты.
- Ограничение Arduino: компилируются только файлы в корне скетча и рекурсивно в `src/`. Хостовые инструменты кладутся вне папки скетча (`tools/`).
- Плата сейчас подключена к ноуту пользователя (Windows, Arduino IDE), а **не к этой машине**. Прошивку и проверку на железе делает пользователь. Отсюда доступа к Serial нет.

## 4. Грабли v1 (проверено чтением кода)

1. Интервалы и «uptime» в v1 считались через `gettimeofday()`. Любая установка времени (NTP, Serial) сдвигала таймеры бездействия, после синхронизации по WiFi гаджет сразу уходил в deep-sleep, а секундомер прыгал. **Интервалы считать только по монотонному времени** (`esp_timer_get_time()` / `millis()`, оба корректируются после light-sleep). Настенное время — отдельно.
2. Логику выполнял только экран, открытый в данный момент. Таймер на чужом экране не срабатывал, а защита от deep-sleep смотрела только на текущий экран → секундомер мог «умереть» во сне. **Состояние и логика (модели) отделены от экранов (видов) и обновляются всегда.** Срабатывание таймера показывается на любом экране и будит дисплей.
3. Без «USB CDC On Boot = Enabled» Serial у SuperMini уходит на UART-пины, а не в USB-C. В v1 это не было учтено в инструкциях.
4. Перед deep-sleep компас оставался в непрерывном режиме 200 Гц. Перед сном датчики нужно переводить в standby.
5. В v1 перед deep-sleep для кнопок пробуждения ext1 не выставлялись **RTC-подтяжки**. На S3 цифровая подтяжка (`pinMode INPUT_PULLUP`) и RTC-подтяжка — разные регистры, а ext1 переводит пин на RTC-мультиплексор, поэтому нужен `rtc_gpio_pullup_en` + `rtc_gpio_pulldown_dis` перед сном. Включать RTC_PERIPH не обязательно: IDF 5.5 фиксирует пины с заданной подтяжкой. Включённый RTC_PERIPH стоит около 1 мкА. См. HW_FACTS esp32s3-power F08–F13. **На железе не проверено.**
6. Превью экранов в v1 рисовались отдельным Python-скриптом, который повторял код вручную, и разошлись с прошивкой. В v2 превью рендерятся **из того же C++-кода**, что и в прошивке.
7. README и подсказки на экране расходились с кодом по кнопкам. Источник правды должен быть один.
8. Порт настройки WiFi сканировал сети при каждом HTTP-запросе (портальные проверки телефона дергают десятки URL). Если портал остаётся, сканировать один раз и кэшировать.

## 5. Принципы

- Молчащая программа — дефект: если датчик не найден, не тот чип или ошибка I2C, это показывается **на экране** человеческим языком (что не так и что проверить) и печатается в Serial. Не просто строка в логе.
- Ничего не утверждать «проверено», если не проверялось на железе. Чек-лист проверки на железе — часть результата.
- Код читаемый, модульный, без магических чисел в разметке экранов (единая сетка и тема).
- Документация (README) на русском, комментарии в коде на английском, коротко.

## 6a. Критические факты из `docs/HW_FACTS.md` (имеют приоритет над любой спецификацией)

Полный лист с источниками лежит в `docs/HW_FACTS.md`: 211 фактов, 7 доменов. Перекрёстно проверен только SHT4x, остальное — один источник, но многое доказано компиляцией на ядре 3.3.12 (IDF 5.5.5).

1. **U8g2 `*_2ND_HW_I2C` на ESP32 core 3.3.12 — тихая заглушка.** `WIRE_INTERFACES_COUNT` в ядре не определён, поэтому байтовый колбэк второй шины компилируется в `return 1` без I/O. Прошивка собирается, `begin()` «успешна», а **дисплей остаётся чёрным без единой ошибки** (доказано компиляцией, HW_FACTS u8g2 U2–U3). Решение: собственный байтовый колбэк поверх `Wire1` (u8g2 U8, около 15 строк, скомпилирован) на основе `u8g2_Setup_ssd1306_i2c_128x64_noname_f`. Колбэк должен запоминать ошибки `endTransmission()`, чтобы отсутствие дисплея было видно. Порядок: `Wire1.begin(10, 11, 400000)` **до** `u8g2.begin()`. Вариант `HW_I2C` для `Wire` (первая шина) не подходит — она занята датчиками.
2. **I2C в 3.3.12** (HAL `esp32-hal-i2c-ng`): `endTransmission()` без данных → probe, NACK адреса = 2. С данными любой NACK = 4. `begin(sda,scl,0)` даёт 100 кГц, таймаут по умолчанию 50 мс, внутренние подтяжки слабые.
3. **SHT4x**: все команды однобайтные. 0xFD high, 0xF6 med, 0xE0 low, 0x89 serial, 0x94 soft reset. Нагреватель: 0x39 200 мВт 1 с, 0x32 200 мВт 0.1 с, 0x2F 110 мВт 1 с, 0x24 110 мВт 0.1 с, 0x1E 20 мВт 1 с, 0x15 20 мВт 0.1 с. Каждая команда нагревателя заканчивается измерением, а результат «горячий». **Пробовать SHT4x раньше SHT3x**: проба SHT3x портит первое чтение SHT4x. Однобайтные команды SHT3x 0x24xx/0xE000 совпадают с командами SHT4x, безопасные — 0x2C06 / 0x3780 / 0xF32D. CRC-8 poly 0x31 init 0xFF. SHT45 бывает только на 0x44.
4. **Магнитометры (автодетект)**: QMC5883L 0x0D (ID-регистр 0x0D=0xFF — слабый признак, в ранней ревизии регистр зарезервирован). QMC5883P 0x2C (рег. 0x00 = 0x80, данные 0x01–0x06, статус 0x09, CTRL1 0x0A, CTRL2 0x0B; **в популярных сторонних драйверах значения регистров неверные**, брать из даташита QST, см. HW_FACTS qmc5883p). HMC5883L 0x1E (ID 0x0A–0x0C = 'H','4','3'; данные X,Z,Y, MSB first; DRDY активный LOW, импульс 250 мкс, а у QMC DRDY активный HIGH уровнем). Бывает «DA 5883» на 0x1E с HMC-совместимой картой и сломанным статусом.
5. **Время**: `esp_timer_get_time()`/`millis()` компенсируются после ручного light-sleep, а тики FreeRTOS **нет** (`xTaskGetTickCount` теряет время сна). После deep-sleep millis начинается с ~0, а `time()`/`gettimeofday()` продолжают идти (RTC). RTC_DATA_ATTR переживает deep-sleep. Источник RTC slow clock — внутренний RC ~136 кГц, дрейфует с температурой, поэтому время через сон неточное.
6. **Сон S3**: RTC-пины GPIO0..21 (все кнопки и DRDY подходят). ext1: только `ANY_LOW`/`ANY_HIGH`, без уровней по пинам. Новое API — `esp_sleep_enable_ext1_wakeup_io`. Нет `esp_deep_sleep_enable_gpio_wakeup` и т.п. Wake-источники **остаются включёнными** до `esp_sleep_disable_wakeup_source`. Light-sleep GPIO-wake работает на любом пине (`GPIO_INTR_LOW_LEVEL`), какой пин разбудил — не сообщается, нужно читать уровни. Удержание кнопки в deep-sleep с подтяжкой 45 кОм стоит ~73 мкА.
7. **USB**: Serial = HWCDC (USB-Serial/JTAG). В light-sleep IDF отключает USB-пады, хост видит отвал. `Serial` (operator bool) = подключён CDC-терминал, `HWCDC::isPlugged()` = есть USB-хост (SOF). Deep-sleep = отключение и переподключение USB.
