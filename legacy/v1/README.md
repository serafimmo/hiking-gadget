# Hiking Gadget — ESP32-S3 SuperMini

Походный мультитул на ESP32-S3 с OLED-каруселью из 5 экранов:
**Часы · Секундомер · Таймер · Компас · Настройки**.

Превью всех экранов: общий лист `screens_preview.png` + отдельные PNG в
папке `screens/` (генерятся `python tools/render_screens.py`).

## Железо

| Компонент | Шина | Пины | I2C адрес |
|---|---|---|---|
| SSD1306 OLED 0.96" | Wire1 | SCL=11, SDA=10 | 0x3C |
| SHT45 (темп/влажность) | Wire | SCL=7, SDA=8 | 0x44 |
| QMC5883L компас (GY-273) | Wire | SCL=7, SDA=8 | 0x0D |
| 4 кнопки | GPIO | K1=4, K2=5, K3=6, K4=1 | — |
| Компас DRDY | GPIO | 12 | — |
| Батарея (опц.) | ADC | GPIO2 + делитель 100k/100k | — |

> ⚠️ **GPIO1 (K4)** на ESP32-S3 совмещён с USB D−. Если синхронизация
> времени идёт через USB-Serial и K4 ведёт себя странно — перенесите K4
> на GPIO2/GPIO3 в `src/config.h` (если GPIO2 занят батареей — на GPIO3).

## Управление

- **K1(↑) / K2(↓)** — листать экраны влево/вправо (карусель).
- **K3(#) / K4(*)** — действия текущего экрана (подсказки внизу экрана).
- Экран гаснет по таймауту (настраивается), любая кнопка будит.
- На экране **Часов** в верхней строке рядом с таймзоной — точка росы
  `DP` (при жаре вместо неё «ощущается как» `HI`).
- На **Компасе** K3 запоминает текущий курс как цель (`tgt`, маркер на
  кольце), K4 — сбрасывает. Удобно держать азимут на тропе.

## Сборка (Arduino IDE)

1. Library Manager → установить:
   - Adafruit SSD1306
   - Adafruit GFX Library
   - **U8g2_for_Adafruit_GFX** (именно мост, не обычный «U8g2»)
   - Adafruit SHT4x Library
   - (WiFi, WebServer, DNSServer, Preferences, EEPROM — идут с ESP32-core,
     ставить не нужно)
2. Плата: **ESP32S3 Dev Module**.
3. Открыть `Hiking_Gadget/Hiking_Gadget.ino`, Upload.

## Сборка из командной строки (arduino-cli)

```bash
CLI="/c/Program Files/Arduino IDE/resources/app/lib/backend/resources/arduino-cli.exe"

# компиляция
"$CLI" compile --fqbn esp32:esp32:esp32s3 Hiking_Gadget

# прошивка (подставьте свой порт)
"$CLI" upload -p COM5 --fqbn esp32:esp32:esp32s3 Hiking_Gadget
```

Текущий размер: ~1.04 MB flash (79% с WiFi-стеком), ~49 KB RAM (14%).
Если при заливке не хватит места — выбери в IDE **Tools → Partition Scheme →
Huge APP (3MB)**.

## Диагностика по Serial (первый запуск)

Открой Serial Monitor на **115200**. При старте печатается:

- баннер (модель чипа, причина сброса/пробуждения, свободная память);
- **скан обеих I2C-шин** с пометками устройств и сводкой
  `OLED 0x3C:OK  SHT45 0x44:OK  compass 0x0D:OK` (или `MISSING` — сразу видно
  проблему распайки);
- статус каждой подсистемы (OLED, батарея, часы, SHT45, компас).

Дальше каждые 2 секунды (`LOG_TELEMETRY_MS`) идёт строка телеметрии со **всем,
что приходит с датчиков**:

```
[t+12.345s][TLM] t=23.4C rh=56% dp=14.2C | hdg=045 raw=44.7 xyz=-123,456,-789 | bat=4.01V 85% | scr=COMPASS sync=1 heap=234567
```

Плюс события: нажатия кнопок, смена экрана, сон/пробуждение дисплея, калибровка
компаса, WiFi/NTP. Если OLED не найден — устройство **не виснет**, а работает
«вслепую» и продолжает слать телеметрию (удобно искать причину).

Телеметрия молчит, пока USB-хост не подключён, так что в поле она почти ничего
не стоит. Полностью выключить логирование: `LOG_ENABLED 0` в `src/config.h`.

## Синхронизация времени

RTC-чипа нет — время живёт в ОЗУ и синхронизируется по Serial при старте
(окно 3 секунды после подачи питания):

```bash
python sync_time.py            # автоопределение порта
python sync_time.py COM5       # явный порт (Windows)
python sync_time.py /dev/ttyUSB0
```

Между перезагрузками последнее время сохраняется в EEPROM (грубо, с дрейфом).
Время живёт в аппаратном RTC ESP32 (`settimeofday`), поэтому идёт даже во
время light-sleep — и часы, и секундомер/таймер остаются точными.

## WiFi: точное время по интернету (NTP)

WiFi **выключен по умолчанию** и включается только по запросу — это главная
экономия батареи. Два пункта в Настройках:

- **WiFi setup** — гаджет поднимает свою точку доступа `HikeGadget-Setup`
  (пароль `hike1234`). Подключись телефоном → откроется страница (или зайди на
  `192.168.4.1`) → выбери свою домашнюю сеть, введи пароль → **Save**. Гаджет
  подключится, возьмёт точное время по NTP и **выключит WiFi**. Сеть
  сохраняется (NVS).
- **Sync time (WiFi)** — быстрый повторный синк по уже сохранённой сети.

К3 в портале — выход. Пароль AP меняется в `src/config.h` (`WIFI_AP_PASS`).

## Калибровка компаса

Настройки → **Calibrate compass**. Медленно вращай устройство «восьмёркой»
по всем осям ~25 секунд — собираются min/max по X/Y, вычисляется hard-iron
offset и сохраняется в EEPROM. K2 — сохранить сразу, K1 — отмена.
Также есть ручная поправка магнитного склонения (**Declination**, K2 +1°,
долгое нажатие K1 −1°).

## Энергопотребление (аккум ~300 мАч)

Заложено несколько мер:

| Мера | Эффект |
|---|---|
| WiFi off кроме NTP/портала | убирает главный потребитель (~80–120 мА) |
| CPU 80 МГц (вместо 240) | −~30% в активном режиме |
| Экран гаснет по таймауту | OLED ~10–15 мА только когда нужен |
| **Light-sleep** в простое | CPU ~1–2 мА вместо ~40 мА |
| **Deep-sleep** после ~10 мин простоя | ~десятки мкА; просыпается по любой кнопке |
| Калиброванный ADC, опрос раз в 30с | минимум на измерения |

Грубая оценка от 300 мАч:
- экран постоянно включён: **~5–6 часов**;
- обычный режим (экран вспыхивает на минуту, остальное — сон): **несколько суток**.

Таймер тикает даже при погашенном экране и **будит дисплей**, когда время вышло.
Если запущен секундомер/таймер, авто-deep-sleep не срабатывает (экран лишь
гаснет), чтобы не потерять отсчёт.

**Deep-sleep** включается сам после `AUTO_DEEP_SLEEP_SEC` (по умолч. 10 мин)
простоя или вручную: Настройки → **Power off**. Просыпание — любая из кнопок
K1–K4 (ext1-wake с RTC-pullup). Время переживает deep-sleep: ESP32 RTC идёт,
и при пробуждении валидное время не перезатирается из EEPROM.

> Делитель батареи 100k/100k постоянно потребляет ~21 мкА — при долгом
> хранении это ~15 мАч/месяц. Для «выключения» гаджета лучше разрывать
> питание физически.

> Включается/выключается light-sleep пунктом **Low power** в настройках
> (по умолчанию ON). При отладке через USB-Serial удобнее OFF.

## Структура кода

```
Hiking_Gadget.ino          точка входа (setup/loop)
src/
  config.h / types.h       пины, константы, общие типы
  hal/      i2c_buses · display · buttons · battery · splash · ui · power
  drivers/  sht45_driver · compass_driver
  services/ clock · settings_store · ui_manager · net
  screens/  home · stopwatch · timer · compass · settings
```

> Все модули лежат под `src/` намеренно — Arduino компилирует `.cpp`
> только в корне скетча и рекурсивно в `src/`. Папки вне `src/` он
> игнорирует (именно из-за этого первая сборка падала на линковке).

## UI-сетка (128×64)

Единая раскладка для всех экранов:

```
y 0..8    верхняя строка: заголовок (слева) · точки-страницы (центр) · батарея (справа)
y 9       разделитель
y 11..53  контент экрана
y 54      разделитель
y 56..63  подсказки кнопок K1 / K2
```
