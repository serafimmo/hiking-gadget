# Hiking Gadget v2

Походный гаджет на ESP32-S3 SuperMini: часы с часовыми поясами, секундомер с кругами, таймер с сигналом, компас с целью и калибровкой, температура и влажность (SHT45), настройки и диагностика. Экран OLED 0.96" 128×64 с четырьмя кнопками `^ v # *`.

Прошивка написана заново (v2) по спецификации `docs/SPEC.md`. Старая версия лежит в `legacy/v1/`.

> **Статус:** код собран и проверен на компьютере: 157 тестов, рендер всех 85 экранов тем же кодом, аудит раскладки и кнопок, прошивка 478 КБ без предупреждений. **На железе ещё не проверялось.** Порядок проверки — `docs/HW_CHECKLIST.md`.

Все экраны: [`docs/screens/contact_sheet.png`](docs/screens/contact_sheet.png). Кнопки на каждом экране: [`docs/BUTTONS_RU.md`](docs/BUTTONS_RU.md) (по-английски — [`docs/BUTTONS.md`](docs/BUTTONS.md)); таблицы сгенерированы из кода прошивки, поэтому всегда совпадают с ней.

## 1. Железо и подключение

| Узел | Шина | Пины ESP32-S3 SuperMini | Адрес |
|---|---|---|---|
| OLED SSD1306 128×64 | `Wire1`, 400 кГц | SDA **10**, SCL **11** | 0x3C (или 0x3D) |
| Кнопки модуля K1 K2 K3 K4 | — | **4, 5, 6, 1** (на GND, подтяжка внутренняя) | — |
| SHT45 (или SHT3x) | `Wire`, 100 кГц | SDA **8**, SCL **7** | 0x44 (или 0x45) |
| GY-273: QMC5883L / QMC5883P / HMC5883L | `Wire`, 100 кГц | SDA **8**, SCL **7**; DRDY → **12** (не обязателен) | 0x0D / 0x2C / 0x1E |

Питание всех модулей — 3.3 В. Какая кнопка какой символ (`K1=^`, `K2=v`, `K3=#`, `K4=*`), пока предположение. Проверяется за минуту на экране Settings › Diagnostics › Buttons (шаг 3 чек-листа). Если не совпадёт, поправить одну строку `kKeyPins` в `src/config/board_pins.h`.

Магнитометр определяется по регистру ID, а не по надписи на плате. Поддержаны QMC5883L, QMC5883P, HMC5883L и клон «DA 5883» со сломанным битом готовности (он читается по таймеру и помечается `W-MAG-NOSTATUS`).

## 2. Прошивка из Arduino IDE 2.x (Windows)

1. **Boards Manager**: «esp32 by Espressif Systems» версии **3.3.x** (разработано на 3.3.12).
   **Library Manager**: **U8g2** by olikraus (2.36.x или новее). Других библиотек не нужно.
2. **Меню Tools**:

   | Пункт | Значение |
   |---|---|
   | Board | **ESP32S3 Dev Module** |
   | USB CDC On Boot | **Enabled**: иначе Serial уходит на UART-пины и USB молчит. Прошивка с выключенным пунктом не соберётся: `#error` назовёт этот пункт |
   | USB Mode | Hardware CDC and JTAG |
   | Upload Mode | UART0 / Hardware CDC |
   | Flash Size | 4MB |
   | Partition Scheme | Default 4MB with spiffs |
   | PSRAM | **Disabled** (не «OPI PSRAM») |
   | Flash Mode | QIO 80MHz (не 120 МГц) |
   | CPU Frequency | любая (прошивка сама ставит 80 МГц) |
   | Erase All Flash Before Sketch Upload | **Disabled**: сохраняет настройки и калибровку |

3. Открыть папку проекта: `Hiking_Gadget.ino` лежит в её корне. Нажать **Upload**.
4. **Если порта нет или загрузка не идёт** (гаджет в глубоком сне или прошивка зависла): сначала нажать любую кнопку гаджета. Не помогло — зажать **BOOT**, коротко нажать **RESET**, отпустить BOOT, загрузить, затем нажать RESET.
5. **Serial Monitor**, 115200: появится отчёт о загрузке. Если монитор открыт позже, отчёт повторится автоматически; можно и набрать `INFO`.

### Без Arduino IDE (готовый образ, из браузера)

1. Взять файл `hiking_gadget_v2.0.0_merged.bin` (присылается отдельно; собирается командой `tools/build.sh fw`, лежит в папке сборки как `Hiking_Gadget.ino.merged.bin`).
2. Открыть в Chrome или Edge `https://espressif.github.io/esptool-js/` → **Connect**, выбрать порт гаджета (если порта нет — нажать кнопку гаджета или BOOT+RESET, как в п. 4 выше).
3. Flash Address **0x0**, выбрать файл, **Program**. После окончания нажать RESET.

Образ полный (загрузчик, таблица разделов, прошивка), поэтому стирает сохранённые настройки — для первой прошивки это нормально.

### Если менеджер библиотек не скачивает U8g2

Скачать ZIP `https://github.com/olikraus/u8g2_arduino` → Sketch › Include Library › Add .ZIP Library.

## 3. Время

Часы бывают **точными** (синхронизированы с компьютером или введены вручную) или **приблизительными**. Приблизительные — после прошивки (время сборки) и после полного отключения питания (последняя сохранённая точка). Тогда на Home горит метка `SYNC?`.

Если экран погашен, **сначала нажмите любую кнопку гаджета**. Спящий гаджет компьютер может не видеть до ~35 с, выключенный — до нажатия.

- **Из браузера** (ничего не нужно ставить): закрыть Serial Monitor, открыть файл `tools/sync/hg_sync.html` в Chrome или Edge → **Connect** → выбрать порт гаджета → **Sync time**. **Check drift** только покажет расхождение, **Set zone = PC zone** поставит пояс, как на компьютере. Страница работает без интернета.
- **Скрипт** (нужен Python): закрыть Serial Monitor, затем
  ```
  py -m pip install pyserial
  py tools\sync_time.py
  ```
  `--check` только покажет расхождение (уход часов), `--tz MSK` заодно поставит часовой пояс.
- **Без инструментов**: в Serial Monitor (окончание строки «Newline») набрать `TIME 2026-10-11 19:42:00` и нажать Enter, когда на телефоне :00.
- **На гаджете**: Settings › Set time (часы, минуты, день, месяц, год; секунды станут 00).

Часового кварца у SuperMini нет, во сне время считает внутренний RC-генератор. Насколько он уходит, покажет шаг 16 чек-листа.

## 4. Кнопки, коротко

- `^` / `v` — страницы карусели (Home, Секундомер, Таймер, Компас, Настройки), в списках и пикерах — вверх/вниз.
- `*` — главное действие страницы (старт/стоп, метка, открыть, сохранить, OK).
- `#` — второе действие (круг, +1 мин, следующий пресет, назад, отмена, детали).
- Справа от экрана нарисованы значки только тех кнопок, у которых сейчас есть действие. Нет значка — кнопка ничего не делает.
- Удержание всегда видно: значок кнопки заполняется снизу. Опасные действия (сброс, выключение) срабатывают только по удержанию.
- Если экран тёмный или тусклый, первое нажатие только включает его.
- Выключить гаджет: удерживать `*` на Home 1,5 с. Включить: любая кнопка.

Полная таблица по всем экранам: [`docs/BUTTONS_RU.md`](docs/BUTTONS_RU.md) (по-английски — [`docs/BUTTONS.md`](docs/BUTTONS.md)).

## 5. Если что-то не так: коды ошибок

Ошибка видна на экране (карточка, метка, значок ⚠ в строке статуса), а подробности уходят в Serial. Ничего не отбрасывается молча.

| Код | Что значит | Что делать |
|---|---|---|
| `E-OLED-NONE` | Дисплей не ответил ни на 0x3C, ни на 0x3D | Проверить SDA10/SCL11 и питание дисплея. Гаджет работает без экрана, Serial печатает сообщение каждые 10 с |
| `E-OLED-IO` | Ошибки передачи на дисплей | Провода дисплея; повторная инициализация идёт сама |
| `E-SHT-NONE` | Датчик температуры не отвечает (0x44/0x45) | Проверить SDA8 SCL7 3V3; датчик ищется снова с паузами 5→10→30→60 с |
| `E-SHT-UNK` | По адресу 0x44 что-то есть, но не SHT4x/SHT3x | Проверить, что за модуль |
| `E-SHT-CRC` / `E-SHT-IO` | Три плохих чтения подряд | Провода, помехи; датчик переопрашивается |
| `I-SHT-3X` | Найден SHT3x вместо SHT4x | Всё работает, только импульсного нагревателя нет (Heater = N/A) |
| `W-HEAT-HOT` | Нагрев пропущен: температура выше 60 °C | Ничего: это защита |
| `E-MAG-NONE` | Магнитометр не найден (0x0D/0x2C/0x1E) | Провода GY-273; Compass покажет, кого искали |
| `E-MAG-UNK` | По адресу ответил чип с неизвестным ID | Посмотреть ID на экране Compass / Diagnostics |
| `W-MAG-ID` | QMC5883L с неожиданным ID, работаем как с QMC5883L | Сообщить ID |
| `E-MAG-STUCK` | Магнитометр перестал давать данные | Перезапускается сам (не чаще раза в 5 с) |
| `W-MAG-NOSTATUS` | Чип на 0x1E со сломанным битом готовности («DA 5883») | Работает по таймеру, ничего делать не нужно |
| `W-MAG-SAT` | Насыщение: рядом сильное поле | Убрать металл/магниты |
| `I-MAG-UNCAL` / `W-MAG-CALCHIP` | Нет калибровки / калибровка от другого чипа | Compass › `#` — откалибровать |
| `E-I2C-STUCK` | Линия SDA8 зажата низким уровнем даже после восстановления | Отключить провода датчиков, искать замыкание |
| `W-I2C-REC` | Шина датчиков восстановлена | Проверить провода, если повторяется |
| `E-KEY-STUCK` | Кнопка нажата 10 с подряд (или мешала сну, или будила без нажатия) | Отпустить или проверить замыкание на GND; кнопка игнорируется, пока не отпустится на 1 с |
| `E-NVS` | Память настроек недоступна или запись не удалась | Настройки работают до перезагрузки; тост «Not stored: storage» |
| `W-CFG-RESET` | Сохранённое значение настройки было неверным и сброшено | Карточка назовёт, какое |
| `W-CLK-LOST` | После отключения питания время восстановлено приблизительно или не задано | Синхронизировать (раздел 3) |
| `W-SYNC-REJ` | Синхронизация отклонена | Проверить часы компьютера |
| `W-RST-CRASH` | Перезапуск после сбоя; состояние восстановлено (после трёх подряд — не восстанавливается) | Прислать вывод `LOG DUMP` |
| `W-BROWNOUT` | Перезапуск из-за просадки питания | Батарея/кабель |
| `E-PWR-SLEEP` | Глубокий сон не удался | Гаджет остаётся включённым; прислать лог |
| `E-RTC-LOST` | Память сна повреждена: таймер, секундомер и цель сброшены | Проверить таймер; экран включается сам |

## 6. Консоль (Serial Monitor, 115200, окончание строки — Newline)

| Команда | Что делает |
|---|---|
| `PING` | ответ `PONG HG2 2.0.0 <uptime_ms>` |
| `HELP`, `INFO` | список команд; отчёт о загрузке и текущее состояние |
| `TIME <unix>[.ms]`, `TIME YYYY-MM-DD HH:MM[:SS]`, `TIME?` | установить / посмотреть время |
| `TZ <id>`, `TZ?` | часовой пояс (`MSK`, `CET`, `NYC`, …) / список поясов |
| `SCAN`, `SHT`, `HEAT`, `MAG <s>`, `KEYS` | скан шин, замер, тест нагревателя, поток сырых данных магнитометра, состояние кнопок |
| `GET <key>`, `SET <key> <value>` | настройки: `tz scr bri anim aoff lslp tunit toff heat hpw decl mnt ndl` |
| `LOG E/W/I/D`, `LOG DUMP`, `TLM <s>` | уровень лога, последние 48 строк, телеметрия раз в s секунд (0 — выкл.) |
| `REBOOT`, `FACTORY YES` | перезагрузка; стереть все настройки |

Каждый ответ начинается с `OK` или `ERR <причина>`. Каждый `ERR` дублируется тостом на экране.

## 7. Проверка на железе

## 8. Для разработки (Linux)

```
tools/build.sh all       # lint + заголовки + тесты + рендер + эталоны + аудит + прошивка
tools/build.sh test      # только тесты на ПК (make test ONLY=<часть имени> — выборочно)
tools/build.sh sanitize  # те же тесты под AddressSanitizer + UBSan (дольше)
tools/build.sh render    # все экраны в PNG: /dev/shm/arduino-esp32/build/hg2-host/screens/
tools/build.sh fw        # прошивка ESP32-S3 (arduino-cli, FQBN esp32:esp32:esp32s3:CDCOnBoot=cdc)
tools/build.sh golden    # сравнить экраны с эталонами tools/host/golden/ попиксельно
tools/build.sh golden-update   # принять новые экраны как эталон (после просмотра golden_diff/*.png)
tools/build.sh docs      # обновить docs/screens, docs/BUTTONS.md и docs/BUTTONS_RU.md
```

Слои: `src/core` (чистая логика) → `src/drivers` (датчики поверх интерфейса I2C) → `src/ui` (экраны поверх C API U8g2) → `src/app` (сервисы и ядро приложения) → `src/hal` (только ESP32). Всё, кроме `hal/`, компилируется и тестируется на ПК: те же экраны рендерятся в PNG, весь цикл прошивки гоняется с поддельными портами (`tools/host/fakes/world.h`).

### Что пока известно только на бумаге (проверяется чек-листом)

Соответствие K1..K4 символам и положение значков у кнопок; SHT45 или SHT3x; какой магнитометр и как он повёрнут; пробуждение кнопками из глубокого сна (ext1 + RTC-подтяжки); поведение USB при лёгком сне; уход внутреннего RC-генератора; яркость панели; ток во сне; нагрев SHT от платы; длительность остывания после нагревателя; время вывода кадра. Полный список (23 вопроса, что в прошивке на каждый случай и какой шаг его закрывает) — в конце [`docs/HW_CHECKLIST.md`](docs/HW_CHECKLIST.md).
